# Fit Plan Preflight

לפני כל שינוי משמעותי בפרויקט, להריץ preflight קצר.

## Product Preflight

- האם השינוי משרת תזונה/משקל או שהוא מרחיב מדי את ה-MVP?
- האם הוא מתאים ל-PWA אישי לנועם בלבד?
- האם הוא שומר על שימוש מהיר בטלפון?
- האם יש השלכה על פרטיות/בריאות/אלרגיות?

## Existing Solutions Preflight

לפני בניית רכיב מותאם אישית, לבדוק בקצרה:

- API או מאגר תזונה חינמי/פתוח.
- תמיכה במוצרים ישראליים.
- מגבלות שימוש ועלות.
- האם יש ספרייה קיימת לפירוק טקסט/יחידות/כמויות.
- האם פתרון קיים מספיק טוב או שצריך custom.

## Technical Preflight

- האם השינוי נשאר בתוך `/home/noam/.openclaw/workspace/fit-plan`.
- האם אין קריאה/העתקה מפרויקטים אחרים בלי אישור.
- האם מודל הנתונים מכסה את השינוי.
- האם יש דרך לבדוק את השינוי מקומית.

## Stop Conditions

- מידע רפואי/תזונתי מוצג כהמלצה מוסמכת במקום ככלי מעקב.
- אפרסק נכנס להצעות אוכל.
- ערבוב בשר וחלב מוצע בתפריט.
- השינוי דורש פרסום חיצוני או שליחת נתונים בלי אישור.
- נדרש שימוש בתשלום בלי אישור מפורש.
